# 회사 목록 페이징 진행 기록

기준일: 2026-11-08
상태: 회사 10개씩 조회와 번호 링크 자동 생성까지 구현. 5개 번호 묶음과 화살표 이동은 다음 단계.

## 직전 커밋 이후 한 일

- 기준 커밋: `5f28a49` (회사 수정에도 이름 중복 검사 추가).
- 홈 화면의 회사 목록을 ID 오름차순으로 최대 10개씩 조회한다.
- 주소의 `page`를 받아 서비스에서 PageRequest로 조회 조건을 만든다. 주소는 0부터, 화면 번호는 1부터 센다.
- Page의 회사 목록을 DTO로 바꾸고 전체 페이지 수 등의 정보를 유지한다.
- PageNumberDto에 표시 번호와 요청 번호를 함께 담는다. Mustache 반복문으로 링크를 자동 생성한다.
- 현재·전체 페이지 수를 회사 목록 아래에 표시한다.
- data.sql의 예시 회사를 2개에서 11개로 늘려 페이지가 나뉘는지 확인한다.
- 회사 응답 DTO 변환 메서드 이름을 createCompanyResponseDto로 맞췄다.
- 자체 로그인·구글 소셜 로그인·사용자별 기록 관리와 배포의 진행 순서를 문서에 정리했다.

## 현재 요청 흐름

`/?page=1` → HomeController → CompanyService.indexPage(1) → PageRequest(1, 10, ID 오름차순) → Repository → 회사와 페이지 정보 → DTO 변환 → Model → Mustache.

- PageRequest: DB 조회에 전달할 페이지 번호·크기·정렬 조건.
- Page: 조회된 회사 목록과 전체 개수·페이지 수 등을 담는 결과.
- getContent(): 회사 목록을 꺼낸다. getTotalPages(): 전체 페이지 수를 꺼낸다.
- PageNumberDto: displayNumber는 화면 번호, requestPageNumber는 주소의 page 값이다.
- totalPages: DTO 목록. companiesTotalPages: 전체 페이지 수. 이름은 비슷하지만 담는 값이 다르다.
- 기존 GET /api/companies의 전체 목록 응답은 유지한다.

## 확인한 범위

- 실제 서버 GET: 회사 11개가 page=0에서 10개, page=1에서 1개로 나뉘며 응답은 200이다.
- 두 응답의 현재·전체 페이지 표시와 번호 1의 주소 page=0, 번호 2의 주소 page=1을 확인했다.
- 사용자가 실제 화면에서 회사 목록과 번호 링크 표시를 확인했다.
- Java 17 컴파일과 기존 GlobalExceptionHandlerTest 7건을 실행해 통과했다.
- 기존 GlobalExceptionHandlerTest는 기존 오류 응답을 검증하는 자산이다. 이 테스트의 통과를 페이징 자동 테스트 또는 사용자의 독립 테스트 작성 경험으로 표현하지 않는다.

## 다음에 할 일

1. 현재 페이지가 속한 5개 번호 묶음의 시작·끝을 계산한다. 숫자 예시를 이해한 뒤 작성한다.
2. 반복문 범위를 그 묶음으로 제한하고 실제 존재하는 번호까지만 표시한다.
3. `<<`는 첫 페이지, `<`는 이전 묶음 첫 페이지, `>`는 다음 묶음 첫 페이지, `>>`는 마지막 페이지로 연결한다.
4. 번호 영역을 목록 아래 가운데에 배치하고 현재 페이지를 구분한다.
5. 빈 목록, 범위 밖 페이지, 마지막 항목 삭제, 등록·수정 후 페이지 위치를 확인하고 처리 기준을 정한다.

## 확정한 화면 기준

- 회사는 한 페이지에 최대 10개, 페이지 번호는 최대 5개씩 묶는다.
- 3페이지의 >는 6페이지, 8페이지의 >는 11페이지다.
- 8페이지의 <는 1페이지, 13페이지의 <는 6페이지다.
- <<는 1페이지, >>는 실제 마지막 페이지다.
- 전체 7페이지라면 둘째 묶음에는 6, 7만 표시한다. 존재하지 않는 이동은 제공하지 않는다.
- 번호 5개는 표시 단위이며 저장할 회사 수를 제한하지 않는다.
- 지원내역 자체의 페이징은 이번 범위 밖이다.

## 학습 방식과 현재 진도

사용자가 직접 코드를 작성하고, 설명·힌트를 받은 뒤 검토와 실행 확인을 진행한다. 새로운 개념은 한 번에 하나씩 다룬다. 다음 단계의 기능을 미리 구현하지 않는다. 숫자 목록 → DTO 목록 → Mustache 반복 출력까지 작성했다. 다음 수업은 5개 묶음의 시작 번호 계산이다.
